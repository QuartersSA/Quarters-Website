# خطة: نظام تأسيس الفروع (Branch Establishment Projects)

> مسودة تخطيط — لم يُنفَّذ منها شيء بعد. مبنية على فحص الكود الحالي (ثلاثة وكلاء استكشاف: الفروع/الصلاحيات، المشتريات/الحسابات، أنماط الواجهة).

## 1. الهدف
صفحة واحدة لكل فرع جديد تجمع: التكاليف (من توقيع عقد الإيجار حتى الافتتاح)، خط زمني لكل قسم، متابعة التطور، وتنبيهات التأخر وتجاوز الميزانية.

## 2. حقائق من الكود تحكم التصميم
| الحقيقة | الأثر |
|---|---|
| جدول `branches` فيه `id, name, location` فقط، بلا حالة | إضافة فرع «قيد التأسيس» الآن يلوّث تقارير المخزون (`CROSS JOIN branches` في 6 تقارير) |
| عقود الإيجار مرتبطة بـ `branch_id` اختياري + `location` نصي | يمكن ربط العقد بالمشروع مباشرة قبل وجود الفرع |
| فواتير المشتريات هي مصدر التكاليف الوحيد (اعتماد، سداد، مرفقات، ضريبة، سجل تدقيق)، وربط الإيجار تم بأعمدة `lease_*` بلا FK | نفس النمط: `project_id` + `project_phase_id` على الفاتورة |
| `validateExpenseAccount` يرفض أي حساب غير `expense` | حسابات التأسيس يجب أن تكون مصروفات (مجموعة `53`)، لا أصول |
| لا يوجد Gantt/مهام مشاريع؛ يوجد Workspace tasks (مساحات/مهام/قوائم تحقق) غير مرتبطة بفرع | نبني جداول خفيفة خاصة بالمشروع؛ الربط بمهام الفريق لاحقاً |
| الصلاحيات: قسم المالية = `can_manage_accounting || can_manage_purchases` | المرحلة الأولى بلا صلاحية جديدة |
| `recharts` موجود؛ لا مكتبة Gantt | خط زمني بـ CSS grid خفيف |

## 3. القرار المحوري: الفرع يُولد عند الافتتاح
- المشروع كيان مستقل (`branch_projects`) يحمل الاسم/المدينة/الموقع.
- `branch_id` فارغ حتى «تأكيد الافتتاح» → عندها يُنشأ صف `branches` (أو يُربط بفرع موجود) وتُحدَّث `branch_id` على كل فواتير المشروع وعقد الإيجار.
- يحمي التقارير التشغيلية من فرع لم يفتح بعد، بلا تعديل 6 تقارير.

## 4. نموذج البيانات (كلها `CREATE TABLE IF NOT EXISTS` عبر `ensureBranchProjectsSchema()` ممَيمَز بـ `ensureOnce`)

### `branch_projects`
`id, code (BP-001), name, city, district, address, area_sqm, branch_id NULL, lease_contract_id NULL, status (planning|in_progress|on_hold|opened|cancelled), contract_signed_date, target_opening_date, actual_opening_date, budget_total, manager_employee_id, notes, cover_url, is_active, created_*/updated_*`

### `branch_project_phases` (الأقسام)
`id, project_id, name, sort_order, planned_start, planned_end, actual_start, actual_end, status (not_started|in_progress|done|blocked), budget, weight, progress_override, owner_employee_id, contractor_contact_id, color, notes`

قالب الأقسام الافتراضي (قابل للتعديل لكل مشروع):
1. العقد والإيجار  2. التراخيص والتصاريح (بلدية، دفاع مدني، سجل تجاري فرع، شهادة صحية)
3. التصميم والمخططات  4. الديكور والتشطيب (مقاول)  5. الكهرباء والسباكة والتكييف
6. المعدات (ماكينات، طواحين، ثلاجات)  7. الأثاث واللوحات  8. الأنظمة (POS، كاميرات، إنترنت)
9. التوظيف والتدريب  10. المخزون الافتتاحي  11. التسويق والافتتاح

### `branch_project_tasks`
`id, project_id, phase_id, title, status (todo|in_progress|done|blocked), is_milestone, due_date, done_at, done_by, assignee_employee_id, sort_order, notes`
- لكل قسم قائمة مهام افتراضية (مثال التراخيص: رخصة بلدية، فسح دفاع مدني، سجل تجاري، شهادة صحية للموظفين).
- المعالم (`is_milestone`): تسليم الموقع، اكتمال التشطيب، تركيب المعدات، الافتتاح التجريبي، الافتتاح.

### `branch_project_updates` (سجل التطورات)
`id, project_id, phase_id NULL, body, photos JSONB, created_by_*, created_at`

### `branch_project_attachments`
`id, project_id, phase_id NULL, url, label, kind (contract|permit|design|quote|photo|other), created_*`

### تعديلات على جداول موجودة
- `accounting_purchase_invoices`: `+ project_id INTEGER, project_phase_id INTEGER` (+ index) — عبر `ensureProjectInvoiceLinkColumns()` بنفس نمط `ensureLeaseInvoiceLinkColumns`.
- `accounting_lease_contracts`: `+ project_id INTEGER`.
- `branches`: `+ opened_at DATE, project_id INTEGER` (للعرض فقط؛ لا حالة).
- `accounting_accounts`: مجموعة نظامية جديدة `53 تكاليف تأسيس الفروع` (expense، غير قابلة للترحيل) وأبناء: `5301 إيجار ما قبل الافتتاح، 5302 تراخيص ورسوم حكومية، 5303 تصميم واستشارات، 5304 ديكور وتشطيب، 5305 كهرباء وسباكة وتكييف، 5306 معدات، 5307 أثاث ولوحات، 5308 أنظمة وتقنية، 5309 رواتب وتدريب ما قبل الافتتاح، 5310 تسويق الافتتاح، 5399 أخرى`.

## 5. الحسابات والمنطق (ملف `src/utils/branchProjectMath.js` + اختبارات vitest)
- تقدم القسم = المهام المنجزة / الكل (أو `progress_override`).
- تقدم المشروع = مرجّح بـ `weight` (افتراضي متساوٍ).
- صحة الجدول: `on_track | at_risk | late` — متأخر إذا `planned_end < اليوم` ولم يكتمل؛ في خطر إذا تبقّى < 20% من المدة والتقدم < 60%.
- الأيام المتبقية للافتتاح، الانزياح عن الموعد (أيام).
- الميزانية لكل قسم: مخطط (budget) / ملتزم (إجمالي الفواتير المرتبطة) / مسدد (paid_amount) / المتبقي / نسبة التجاوز.
- إيجار ما قبل الافتتاح: فواتير عقد الإيجار المرتبط حتى `actual_opening_date` تُحسب ضمن المشروع (قسم 1).

## 6. الواجهة (ثيم `uiPurchases`، RTL، دارك/لايت، جوال)
### `/accounting/branch-projects` — قائمة المشاريع
- KPIs: مشاريع قيد التنفيذ، إجمالي الميزانيات، إجمالي المصروف، أقرب افتتاح.
- بطاقة لكل مشروع: الاسم + المدينة، الحالة، العد التنازلي للافتتاح، حلقة تقدم، شريط ميزانية (مصروف/ميزانية)، عدد الأقسام المتأخرة.
- زر «مشروع جديد»: نافذة (اسم، مدينة، موقع، تاريخ توقيع العقد، موعد الافتتاح المستهدف، الميزانية، المدير، ربط عقد إيجار موجود، اختيار قالب الأقسام).

### `/accounting/branch-projects/[id]` — صفحة المشروع
رأس: الاسم، الحالة، العد التنازلي، تقدم %، ميزانية/مصروف، زر «تأكيد الافتتاح».
تبويبات:
1. **نظرة عامة**: خط زمني Gantt (صف لكل قسم: شريط مخطط فاتح + شريط فعلي غامق، خط اليوم، معالم كمعيّنات، نقرة تفتح القسم) + تنبيهات (أقسام متأخرة، تجاوز ميزانية، مهام مستحقة هذا الأسبوع) + آخر 5 تطورات. على الجوال: قائمة أقسام بشريط تقدم.
2. **الأقسام**: بطاقة لكل قسم: تواريخ، مسؤول، مقاول، ميزانية/فعلي، قائمة مهام (تحديد مكتمل، إضافة، مهلة، مسؤول)، تغيير الحالة.
3. **المصاريف**: جدول فواتير المشروع (تاريخ، مورد، قسم، حساب، إجمالي، مسدد، حالة) مع فلتر قسم/حساب/حالة، زر «+ فاتورة» يفتح `PurchaseInvoiceModal` بمشروع وقسم وحساب معبّأة، جدول «الميزانية مقابل الفعلي» لكل قسم، رسم دائري حسب الحساب، تصدير Excel/PDF.
4. **التطورات**: خط زمني يوميات (نص + صور)، فلتر قسم.
5. **المرفقات**: مجموعات حسب النوع (عقد، تراخيص، مخططات، عروض أسعار، صور).
6. **الإعدادات**: تعديل البيانات، ربط/تغيير عقد الإيجار، إعادة ترتيب الأقسام، إيقاف/إلغاء.

### دمج مع الموجود
- `PurchaseInvoiceModal`: حقلا «مشروع تأسيس» و«القسم» (يظهران فقط عند وجود مشروع نشط)؛ اختيار المشروع يحصر الحسابات في `53xx` افتراضياً.
- قائمة فواتير المشتريات: شارة `ProjectBadge` (مثل `LeaseBadge`) تفتح المشروع؛ فلتر «المشروع».
- `LeaseContractModal`: حقل «مشروع تأسيس».
- نظرة عامة المشتريات: بطاقة «فروع قيد التأسيس».
- الشريط الجانبي للمالية: عنصر «تأسيس الفروع» + لوحة الأوامر.

## 7. الـ API (`src/app/api/accounting/branch-projects/…`، كلها `requireAuth(REQUIRE_LEASE)`)
- `route.js` GET (قائمة + ملخصات)، POST (إنشاء + قالب أقسام ومهام في معاملة واحدة).
- `[id]/route.js` GET (مشروع + أقسام + مهام + فواتير + تطورات + مرفقات + حسابات)، PUT، DELETE (إلغاء/حذف نهائي يفك ربط الفواتير لا يحذفها).
- `[id]/open/route.js` POST تأكيد الافتتاح (إنشاء/ربط الفرع، تحديث `branch_id` على الفواتير والعقد، 409 إن بقيت معالم غير مكتملة إلا بـ `force`).
- `[id]/phases/route.js` POST/PUT/DELETE، `[id]/tasks/route.js`، `[id]/updates/route.js`، `[id]/attachments/route.js`.
- `templates/route.js` GET قالب الأقسام الافتراضي.
- سجل التدقيق: `logPurchaseAudit` بـ `entity_type = branch_project`.

## 8. مراحل التسليم
**المرحلة 1 — الأساس (قابل للاستخدام من اليوم الأول)**
جداول + حسابات `53` + API المشاريع/الأقسام/المهام + صفحة القائمة + صفحة المشروع (نظرة عامة بخط زمني، الأقسام، المصاريف) + ربط الفواتير بالمشروع من النافذة + الشارة في قائمة الفواتير + تأكيد الافتتاح + `architecture.md`.

**المرحلة 2 — المتابعة**
التطورات بالصور، المرفقات حسب النوع، الميزانية مقابل الفعلي بالرسوم، ربط عقد الإيجار واحتساب إيجار ما قبل الافتتاح، تصدير، بطاقة في نظرة عامة المشتريات.

**المرحلة 3 — التوسعة**
تنبيهات واتساب أسبوعية (أقسام متأخرة/تجاوز)، صلاحية `can_manage_branch_projects` لمشرف موقع يحدّث المهام والصور من الجوال، تحرير القوالب، سجل أصول ثابتة للمعدات.

## 9. خطة التنفيذ بوكلاء متوازيين (عند الموافقة)
1. **وكيل الخلفية**: الجداول، الحسابات `53`، المسارات، أكواد 409.
2. **وكيل الحسابات**: `branchProjectMath.js` + اختبارات.
3. **وكيل الواجهة**: الصفحتان + الهوكس + مفاتيح الاستعلام.
4. **وكيل الدمج**: نافذة الفاتورة، الشارة، الشريط الجانبي، عقد الإيجار.
5. **وكيل مراجعة** معادٍ يبحث عن أخطاء قبل البناء والدمج.

## 10. أسئلة تحتاج قرارك
1. الفرع يُنشأ عند الافتتاح (مقترح) أم من بداية المشروع؟
2. التكاليف عبر فواتير المشتريات فقط (مقترح) أم أيضاً «مصروف سريع» بلا فاتورة؟
3. قائمة الأقسام الافتراضية: تعديل/حذف/إضافة؟ ميزانية لكل قسم أم للمشروع فقط؟
4. من يحدّث المهام: الإدارة فقط الآن، أم مشرف موقع من الجوال (صلاحية جديدة، مرحلة 3)؟
5. إيجار ما قبل الافتتاح يُحسب ضمن تكلفة المشروع؟ (مقترح: نعم)
6. المعدات مصروف تأسيس الآن، وسجل أصول لاحقاً؟
